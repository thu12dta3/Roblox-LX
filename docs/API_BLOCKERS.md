# API e componentes pendentes

## Estado do ambiente

O launcher oficial Darling foi instalado a partir de um pacote local feito com arquivos da release, mas essa primeira montagem omitiu `/usr/bin/darlingserver`. `darling --version` retornou o identificador `darling HEAD @ e947f0d5` e inicializou `~/.darling`; já a tentativa de executar o fixture Mach-O falhou antes de entrar no programa, com `Failed to start darlingserver` e `Cannot open mnt namespace file: No such file or directory`. Uma revisão do pacote local que inclui `darlingserver` e `darling-coredump` foi preparada, mas ainda não substituiu o pacote instalado. Portanto ainda não há observações de sucesso sobre as APIs macOS. O inventário do MacOBlox abaixo direciona testes, não confirma comportamento neste host.

O projeto Darling atual usa o servidor de kernel em espaço de usuário (`darlingserver`), conforme o [README oficial](https://github.com/darlinghq/darling) e o histórico do [release oficial](https://github.com/darlinghq/darling/releases/tag/v0.1.20260608). Uma página antiga da documentação ainda menciona o módulo de kernel. O artefato oficial Ubuntu contém um launcher host que exige modo setuid root para criar namespaces e mounts; isso torna a instalação uma alteração administrativa. O launcher está instalado, mas o helper do servidor está ausente do pacote local. A busca anterior por `darling-mach` e headers não é um requisito do Darling atual e foi removida do diagnóstico.

## Transferibilidade do audit MacOBlox

- **Darling upstream:** Mach-O loader, `darlingserver`, syscalls/Mach IPC e frameworks são o runtime externo; podem ser detectados e invocados como processo separado. O projeto Darling é GPL-3.0, e submódulos podem ter outras licenças. Nenhum código foi copiado.
- **Adaptadores host conceitualmente transferíveis:** Vulkan direto para gráficos; áudio por PipeWire/PulseAudio; eventos e raw mouse de X11/Wayland; sockets POSIX/DNS do sistema. OpenGL e Zink foram excluídos como backend/fallback. Cada adaptador exige teste independente e revisão de licença.
- **Não transferíveis para este projeto:** `libMacOBloxShims.dylib`, stubs de framework carregados no processo, `patch_startup_throttle.py`, substituição de bytes/funções, patches de transporte/RakNet, alterações FastFlags para forçar renderizador, ocultar device Metal ou injeção/interposição destinada ao cliente. A política exige executável íntegro e não altera protocolos/verificações.
- **Licenças:** MacOBlox declara MIT, mas incorpora bibliotecas/fontes com avisos próprios e conteúdo proprietário Roblox. O repositório foi auditado em `work/MacOBlox-audit` e não será empacotado. Darling permanece dependência externa; a licença proprietária do ROBLOX-LX não altera suas licenças.
